# 光功率计接入前的环境准备复核（2026-11-27）

远端 Windows 上的 LabControl 已进入真实设备工作台。设置页显示 PySide6 6.11.2、PyVISA 1.16.2 正常。打开“准备设备组件”时，公共组件已勾选，R&S VISA 7.2.6 显示“材料已准备，未安装”，FTDI VCP 显示“准备失败”，PL2303 在下载。下面的本地复现使用源码版本 `4338375`；远端发行版的提交号待核对。

## Windows 驱动与安装材料的区别

远端设备管理器已枚举 FTDI USB 串口，显示“这个设备运转正常”，驱动版本 2.12.28.0，数字签名者为 Microsoft Windows Hardware Compatibility Publisher。LabControl 正在准备的固定版本是 2.12.36.20。现场同时看到了可用端口和材料准备失败。仅凭这两项无法判断端口后接的仪器型号或协议。

源码中的串口检测把已绑定签名驱动与清单版本精确比较，其他已绑定版本进入待核实状态。建议将“系统已识别端口、当前驱动版本、清单推荐版本、材料状态”并排列出，让用户先验证现有端口。验收时用已有签名旧驱动的机器复测，能够直接进入所选仪器的只读验证，并单独提示版本差异。[Windows 驱动检测](../../src/lab_control/deployment/windows.py)

## 实机结果

操作员确认型号为 Joinwit JW8105。在已有 FTDI 2.12.28.0 驱动上定向扫描后，LabControl 识别到 JW8105，身份可信度为 `model_only`。通过真实设备工作台连接后，16 个通道均返回功率值。结束记录时程序报告原始数据已保存、分析 CSV 已完成。停止监测后保留设备连接。本次接入无需更换 FTDI 驱动。

同机单独准备 Thorlabs OPM / TLPMX 材料也完成了校验与缓存。该材料适用于其他型号，未参与 JW8105 连接。

另有一项采集速度问题待定位。16 通道监测目标为 0.50 秒/帧，界面报告实际约 17.02 至 17.07 秒/帧。该结果仅对应本次通道与设备配置。复测可分别记录单通道和 16 通道的逐通道请求耗时，再核对界面帧时长及记录时间戳。

## 完成条件

现有“准备所选组件”执行下载、校验和缓存。带安装入口的组件还要启动厂商向导，部分 INF 驱动要按匹配的硬件安装。建议界面分别报告材料校验、Windows 驱动检测、目标设备识别及首个有效功率读数。这样操作员能判断当前该重试下载、安装驱动、插线，还是进入仪器连接。现行流程见[桌面部署与环境修复](../development/desktop-deployment.md)。
