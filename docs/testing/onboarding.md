# 新设备接入流程

修订日期：2026-11-16。

本流程用于新增型号，也用于已有型号新增采集、数据处理或远程控制能力时的补测。先核对资产与接口，再按型号声明和本次授权选择验收项目。每一项结论都要能追溯到相应的样本或测试批次。

## 1. 建立资产和资料

记录完整型号、厂家、可信序列号、固件、接口/选件、驱动和现有输出状态。型号不完整时只建立待补条目，不能猜测协议。实际身份、地址、图片和手册下载存放运行目录；型号包保存官方资料出处、版本、章节及脱敏样本。

同型号不同序列号是不同资产；同一资产的 USB/LAN 等接口分别验证。地址可变，不能用 IP 当永久资产身份。无可靠序列号时保持人工资产号和待核对状态。

## 2. 实现独立型号包

涉及桌面界面时，先在[经典版仪器界面接入规范](../architecture/frontend-design-system.md)中选定参照页，在型号 README 记录参数、读回、共享通道或路由的差异。用模拟设备从公共入口检查所选角色、参数草稿和记录状态。

按[模块规范](../architecture/device-modules.md)建立包、注册项、README、tests 和 hardware。使用[模板](templates/README.md)填写支持范围、单位、组合约束、查询失败行为和恢复边界。公共层只保留通用兼容机制，不加入本型号的命令、范围或历史格式分支。

同时按[部署规范](../development/desktop-deployment.md)登记运行依赖、驱动/SDK、服务和网络要求，在型号元数据 `deployment_components` 引用组件 ID。记录官方来源、版本、安装材料哈希/签名、分发依据、检测/安装与恢复方法；未知项标待补。完成组件登记检查及实际打包回归，不能把依赖下载工作留给最终用户。

通过型号工厂和项目会话验证软件行为，覆盖错误响应、越界、通道隔离、超时不重发、恢复失败。完成导入、模块移除及文档检查；软件通过不自动提升实机状态。

接入自动设置、自动量程或轨迹采集时，核对设置前后的配置和首个有效帧。GUI 连续记录按采集节奏逐帧保存有效帧，CSV 转换周期只决定何时转换。用慢读取、慢写盘的模拟场景验证显示可刷新、缓冲满时明确暂停、停止后排空已接收帧。二进制收尾后释放仪器参数锁，CSV 转换失败单独报告并保留原始记录。旧 API 显式指定保存间隔的行为另作兼容回归。[监测一致性与调度规则](../architecture/live-acquisition.md)

### 按型号能力选择验收项目

从型号包的 `DEFINITION`、当前配置及通道能力取证。计划中写明每项适用的依据。型号未提供的功能注明“不适用”和原因；已声明但本批未执行的项目记 `not_tested`；原计划要执行、因授权或环境受阻的记 `blocked`，写明阻碍。适用性写入说明，批次结果沿用[现有四种状态](records.md#结果分级)。

| 验收项目 | 何时适用、从哪里测 | 通过标准 | 留存证据 |
| --- | --- | --- | --- |
| 采集与保存 | 型号提供测量数据源。按支持的单帧、连续或定时方式，从桌面或 CLI 显式保存 | 重新打开原始记录，实际通道、物理量、单位、时间或频率轴、点数与采集一致。连续记录核对有效帧数与收尾，定时记录核对结束条件；中止或缺帧保留实际完整性 | 数据源、采集参数、原始目录、代表帧、帧数及结束事件 |
| 离线回放与导出 | 型号声明 `offline_processing`。在“数据处理”中断开仪器回放已有记录，按支持的形式导出 | 对照同一份原始数据核验标量趋势或逐帧曲线的通道、单位、横轴和代表点；核对数值导出或图片的通道与坐标。重复处理同一输入可复用完整结果，原始文件哈希一致 | 原始样本及指纹、对照点与容差、导出文件、复用结果。[数据处理指南](../guides/data-processing.md) |
| MCP 能力查询 | 型号接入 Agent 实验。用限定设备和通道的授权调用 `list_devices`、连接后调用 `get_capabilities`；通过槽位选设备时再核对绑定 | 可见设备、通道、可用操作及数据源与型号和授权相符。用隔离软件用例核验越权请求被拒绝 | 授权范围、实际入口（服务方法或 MCP 客户端）、工具名、响应及拒绝原因。槽位查询注明缓存来源 |
| MCP 参数控制 | 本次范围包含远程可写操作。按操作要求取得设置或输出授权，经 `preview_change`、`apply_change` 执行 | 对支持读回的参数比较请求值和实际读回；只提供固件回执的操作核对对应回执并注明限制。记录恢复及最终状态。模拟环境覆盖预览过期或配置冲突、重复请求不会重复写入 | 操作和通道、请求 ID、预览、任务结果、读回或回执、恢复证据 |
| MCP 远程采集 | 已授权的数据源支持 `acquire_once` 或 `start_recording`。按数据源选择单帧或记录任务 | 跟踪 `get_task_status` 至终态，凭本次任务的 `recording_id` 打开记录，核对通道、点数或帧数、单位和完整性。定时采集提前停止须反映在结果中 | 请求 ID、任务 ID 与终态、记录 ID、原始文件和结束条件。[Agent 协作流程](../guides/agent-collaboration.md) |
| MCP 远程指标 | 型号声明对应的 `metric_profiles`。用 `get_processing_capabilities` 核对处理项，提交已知记录给 `start_processing` 或 `start_experiment` | 等待任务结束，经 `get_processing_result` 读回本次结果。核对输入指纹、算法版本及有效参数，逐通道比较预期数值、单位、质量和容差。分别标注模拟来源、不可用指标及不完整记录 | 记录 ID、任务 ID、结果 ID、处理项及版本、期望值计算依据与逐项差异。[指标契约](../architecture/remote-metrics.md) |

**试填示例。** 下表演示如何从型号声明写出测试计划。资产的实测结论填写在相应批次。

| 型号 | 选择的项目与通过条件 | 计划留存的证据 |
| --- | --- | --- |
| [RIGOL M300](../../src/lab_control/instruments/devices/rigol_m300/README.md) | `reading` 标量采集、离线回放与导出。各取一个温度和电压通道，从原始记录选出有时间戳的读数，核对趋势、通道和各自单位。远程指标不适用，型号未绑定处理项 | 原始记录、参考时间点与读数、对应通道的导出 |
| [RIGOL DHO924](../../src/lab_control/instruments/devices/rigol_dho924/README.md) | `waveform` 多通道采集、逐帧回放、按通道导出及远程电压统计。用保存的各通道完整波形独立计算 RMS，与 `voltage.waveform_statistics` v2 对照，单位为 V | 各通道原始电压（V）与时轴（s）、通道导出、逐通道参考值、记录 ID 与结果 ID |
| [DC 开关板](../../src/lab_control/instruments/devices/custom_dc_switch/README.md) | 能力查询及授权开关操作。核对所选操作对应的固件回执，物理输出另行测量。采集、离线回放与远程指标均不适用，型号没有测量数据源或处理声明 | 限定授权下的能力响应、操作和匹配回执、最终状态 |

## 3. 明确本次硬件测试范围

先准备可评审的测试计划：精确资产与接口、目标操作、负载/接线、备份清单、预期读回、比较容差、停止条件、恢复顺序、未测项目。写入或输出操作必须在已有授权范围内；通用文档不自动授权输出或采集启动。

核对正式运行目录、配置、库存及全局锁的最终物理位置。桌面打包环境可能让 AppData 的逻辑路径与物理路径不同，程序会统一使用库存文件解析出的物理运行根目录；不能以另一副本的空闲锁替代正式锁。

## 4. 执行与留档

先只读身份核验，再按计划备份与测试。每次成功、失败、受阻及中止都保存独立批次。异常停止后续测试写入，读取实际状态并执行有依据的恢复；最终状态无法确认时明确写未知。

按[记录规范](records.md)保存原始结果、通信、快照、备份/哈希和 summary.json。关闭/重连、控制及物理测量分别判定，不把设置读回当作物理输出精度。

在每项旁注明证据来自软件模拟、已有实机记录的离线复算、当次实机操作或外部仪器测量。MCP 能力查询、参数控制、远程采集、指标读回分别列项。例如旧批次只有 `mcp_capabilities=passed` 时，只引用该项的查询结论；后续采集或指标需要各自的批次证据。沿用 `summary.json` v1 和现有型号转换器，额外的任务标识、样本及比较细节保存在本批 `results.json` 和证据文件。

## 5. 交付与后续补测

运行离线台账导入及检查，将实际接口、测试范围、恢复、未测/受阻和下一步写入资产说明。型号 README 只维护脱敏结论及限制；具体资产、地址与证据链接在运行目录。

补测另建批次，保留旧失败和恢复过程。所有类别采用[资产状态模板](templates/asset-status.md)，直接更新对应表格；不在现行文档末尾逐次追加测试段落。型号 README 按能力/协议、连接/驱动、范围/约束、测试入口/验证范围、已知限制/待测及扩展方式维护；只保留脱敏结论。硬件入口生成最终摘要后调用公共 `refresh_after_batch`，不自行追加索引或覆盖人工说明。移除型号不删除用户配置、资产历史和实机记录。
